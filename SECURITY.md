# Security Policy

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or Slack.**

You can report a security vulnerability privately using either of the following methods:

1. **GitHub Private Vulnerability Reporting (Recommended):** If enabled on the repository, go to the repository's **Security** tab and click **Report a vulnerability** to open a private Security Advisory directly with maintainers.
2. **Email:** Send an email to **`tech@openfoodfacts.org`** with the details below.

### What to Include

To help us triage and fix issues quickly, please include:

- The affected repository, component, or URL, and version/commit if known.
- A clear description of the vulnerability and its potential impact.
- **Step-by-step reproduction instructions** or a minimal proof-of-concept (reports without a working, verifiable reproduction may be closed as unverified).
- Disclosure of any automated or AI-assisted tools used to generate the report.

## Bounty & Recognition

Please note that Open Food Facts is a non-profit open-source and open-data project, and we do not have funding for a paid bug bounty program.

We are, however, very grateful for your time and expertise, and we will gladly credit you in the security advisory and send you Open Food Facts magnets and stickers :-)
